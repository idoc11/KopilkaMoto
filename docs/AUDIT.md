# Промпт: исправление недостатков KopilkaMoto

Ты — опытный frontend-разработчик (PWA, vanilla JS) и ревьюер безопасности. Работай в репозитории `idoc11/KopilkaMoto`. Ниже — результаты аудита проекта. Исправь недостатки по приоритету, соблюдая ограничения.

## Контекст проекта

KopilkaMoto — мобильное PWA для учёта накоплений на мотоцикл. Интерфейс на русском, хостинг — GitHub Pages, сборки и фреймворков нет.

- `index.html` — всё приложение: CSS и JS (около 45 строк минифицированного кода в одном IIFE).
- `service-worker.js` — офлайн-кеш; `manifest.webmanifest` и `icon.svg` — установка PWA.
- `ai-worker.js` — Cloudflare Worker, прокси к OpenAI Chat Completions; ключ хранится в секрете `OPENAI_API_KEY`.
- `README.md`, `README.txt`, `QA_REPORT.md`, `Копилка-на-мотоцикл-приложение.zip`.

## Жёсткие ограничения

1. **Не потерять данные пользователей.** Ключи `localStorage` `moto-tracker-v1` (операции и настройки) и `kopilkamoto-prefs-v2` (тема, URL прокси) должны читаться как раньше. JSON-копии всех прежних версий должны восстанавливаться: и `app: 'KopilkaMoto'` (`version` 5), и `app: 'moto-savings-tracker'` (`version` 1).
2. Сайт остаётся статическим на GitHub Pages без своего бэкенда. API-ключ никогда не попадает в клиентский код.
3. Vanilla JS без фреймворков. Инструменты разработки (тесты, линтер) разрешены, но сайт должен работать без шага сборки.
4. Язык интерфейса — русский.
5. При любом изменении файлов приложения повышай версию кеша в `service-worker.js`.

## Недостатки

Пометка ✅ — проблема воспроизведена в headless Chromium (Playwright) или подтверждена расчётом.

### P0 — потеря данных и сломанные функции

**1. Операции тихо и навсегда удаляются при запуске** ✅
- **Где:** `index.html`, функции `cleanEntries()` (стр. 34), `load()` (стр. 36), `restore()` (стр. 70).
- **Проблема:** при каждом запуске отбрасываются операции с датой позже `today()` и все записи, не прошедшие валидацию. Следующий `save()` перезаписывает хранилище, и эти данные пропадают навсегда. Хватит того, что часы телефона ушли назад или копию сняли там, где по местному времени уже наступил следующий день.
- **Как воспроизвести:** в хранилище запись на завтра и запись на 2026-01-01 → перезагрузка → добавить операцию. В хранилище остались две записи, «завтрашней» нет.
- **Сделать:**
  - Запрет будущих дат оставить только в форме ввода, при чтении данных его не применять.
  - Если запись действительно повреждена: до перезаписи сохранить сырые данные в отдельный ключ (например, `moto-tracker-v1-raw-<timestamp>`) и показать предупреждение «N записей не удалось прочитать».
  - При восстановлении из JSON показывать, сколько записей импортировано и сколько отброшено. Проверять поле `app` с учётом обоих допустимых значений.

**2. AI-чат перестаёт работать после 3–4 вопросов** ✅
- **Где:** `ask()` (стр. 73), проверка `> 32_000` в `ai-worker.js`.
- **Проблема:** клиент отправляет `messages.slice(-12)` и до 80 операций, не ограничивая размер запроса, а воркер отвечает 413 на всё, что больше 32 000 байт.
  - Размер запросов при ответах около 3000 символов: 17,2 КБ → 22,8 КБ → 28,3 КБ → 33,9 КБ, дальше каждый запрос получает 413. Чат не работает до перезагрузки страницы.
  - Пользователь видит неверную подсказку: «Проверь URL и настройки CORS. HTTP 413».
  - Вопрос без ответа остаётся в `messages`.
- **Сделать:**
  - На клиенте ввести бюджет по байтам: удалять старые сообщения, пока JSON не станет меньше ~24 КБ. Добавить `maxlength` полю вопроса.
  - На воркере обрезать историю, а не отклонять запрос целиком.
  - Показывать текст ошибки из поля `{error}` ответа воркера.
  - При ошибке удалять вопрос без ответа из истории.
  - Добавить кнопку «Очистить чат».

**3. «＋ Добавить доход» открывает форму в режиме «Расход»** ✅
- **Где:** кнопка `.action.primary` (стр. 19) без `data-kind`, обработчик `[data-go]` (стр. 74), `add()` (стр. 68).
- **Проблема:** глобальная переменная `kind` не сбрасывается после сохранения или отмены. После записи расхода кнопка «Добавить доход» открывает форму с выбранным «Расход», и доход сохраняется со знаком минус.
- **Сделать:**
  - Добавить `data-kind="delivery"` главной кнопке и сбрасывать `kind` после сохранения и отмены.
  - Вынести сброс формы в одну функцию `resetForm()`. Сейчас этот код продублирован в `nav()`, `add()` и обработчике `cancelEntry`.

**4. Поле «Часы работы» никогда не скрывается** ✅
- **Где:** `setKind()` (стр. 67), CSS-правило `.field{display:flex}`.
- **Проблема:** правило `.field{display:flex}` перебивает браузерное `[hidden]{display:none}`. Для «Дохода» и «Расхода» поле остаётся видимым (computed display = `flex`).
- **Сделать:** добавить глобальное правило `[hidden]{display:none !important}`.

**5. Данные легко потерять безвозвратно**
- **Проблема:**
  - Всё хранится только в `localStorage`. Safari на iOS удаляет данные сайта, если его не открывали 7 дней (пока приложение не установлено на экран «Домой»).
  - `navigator.storage.persist()` не запрашивается, напоминаний о резервной копии нет.
- **Сделать:**
  - Вызывать `navigator.storage.persist()`.
  - Запоминать дату последней выгрузки JSON и показывать в настройках «Последняя копия: …».
  - Напоминать о копии, если прошло больше 14 дней или добавлено больше 20 операций.
  - Опционально: перейти на IndexedDB.

### P1 — важные

**6. AI получает неверный контекст**
- `Object.values(entries).slice(-80)` берёт операции в порядке добавления, а не 80 самых свежих. После восстановления копии или редактирования порядок произвольный, хотя интерфейс и README обещают «80 последних операций».
- В контекст не попадают `startDate`, `deadline`, `start`, сегодняшняя дата и сумма «нужно в день», поэтому AI не может строить план к сроку.
- **Сделать:** сортировать по `date` и `ts` по убыванию и брать первые 80. Добавить в контекст поля плана и `today`.

**7. Безопасность и надёжность `ai-worker.js`**
- **Нет защиты от чужих запросов.** Проверка `Origin` не защищает: любой скрипт подделывает этот заголовок и тратит платный ключ. Ограничения частоты в коде нет, только совет в README.
  → Добавить rate limiting (биндинг Workers Rate Limiting или счётчик в KV / Durable Object по IP) и дневной лимит запросов или токенов.
- **Неверная обработка ошибок провайдера.** `await response.json()` вызывается до проверки `response.ok`, поэтому не-JSON-ответ провайдера превращается в 400 «Invalid request».
  → Сначала проверять статус; логировать статус ответа OpenAI через `console.error`, не записывая тело запроса.
- **Нет тайм-аута** запроса к OpenAI.
  → Добавить `AbortSignal.timeout(25000)`.
- **Заголовок `null` для чужих Origin.** Для них отдаётся `Access-Control-Allow-Origin: null`.
  → Не ставить этот заголовок вообще.
- **Несовместимые параметры модели.** `max_tokens` и `temperature` не принимаются новыми reasoning-моделями: если сменить `OPENAI_MODEL`, придёт непонятная 502.
  → Использовать `max_completion_tokens` (или Responses API) и не передавать `temperature` моделям, которые её не поддерживают. Проверить актуальность модели по умолчанию `gpt-4o-mini`.
- **Воркер публикуется вместе с сайтом.** Файл лежит в корне репозитория и попадает на GitHub Pages.
  → Перенести в `worker/` вместе с `wrangler.toml`.

**8. Service Worker мешает обновлениям**
- Стратегия cache-first применяется и к `index.html`. Новая версия приходит, только если вручную поменять `CACHE`, и только со второго запуска. Уведомления «Доступна новая версия» нет.
- Кешируется любой GET-запрос к своему origin без ограничений, включая zip-архив, README и воркер.
- Офлайн-фоллбек отдаёт `index.html` на любой неудачный запрос, в том числе на картинки и JSON.
- **Сделать:**
  - Для навигации — network-first (или stale-while-revalidate); cache-first — только для фиксированного списка статики.
  - Фоллбек на `index.html` — только при `request.mode === 'navigate'`.
  - Баннер обновления: `registration.waiting` → `postMessage('skipWaiting')` → событие `controllerchange` → перезагрузка.

**9. Две открытые вкладки затирают данные друг друга**
- Нет обработчика события `storage`: при двух вкладках или окнах сохраняется версия той, что записала последней, операции из другой теряются.
- **Сделать:** слушать `storage`, перечитывать состояние и перерисовывать интерфейс.

**10. Цель и даты захардкожены**
- `BASE=600000`, `DEFAULT_START='2026-12-01'`, `DEFAULT_DEADLINE='2027-03-31'`. Новый пользователь после марта 2027 сразу увидит «Срок плана прошёл».
- Если `deadline <= startDate`, функция `cleanSettings` молча сбрасывает обе даты.
- **Сделать:**
  - Значения по умолчанию считать от сегодняшней даты (например, старт — сегодня, срок — через 4 месяца).
  - Добавить короткий онбординг при первом запуске: «Сколько стоит мотоцикл? Когда хочешь купить?».

**11. Репозиторий и публикация**
- `README.md` велит «сохранить `.github`» и публиковать через GitHub Actions, но папки `.github` в репозитории нет, так что инструкция не работает.
- `Копилка-на-мотоцикл-приложение.zip` — устаревшая версия 1: другой кеш `moto-savings-v2`, копии с `version: 1`, нет достижений. Архив публикуется на Pages и сбивает с толку.
- `README.txt` дублирует `README.md` и устарел: кнопки «Скачать резервную копию» и «Восстановить из копии» теперь называются «Скачать JSON» и «Восстановить JSON».
- **Сделать:**
  - Удалить zip и объединить README в один файл.
  - Добавить `.github/workflows/pages.yml` (`actions/upload-pages-artifact` + `actions/deploy-pages`), который публикует только файлы приложения.

**12. Иконки PWA**
- Иконка одна: SVG с `"purpose": "any maskable"`.
  - Совмещать значения в `purpose` не рекомендуется.
  - Кружок с плюсом (центр 91,91, радиус 18) выходит за безопасную зону maskable и обрезается.
- PNG 192 и 512 нет.
- Нет `apple-touch-icon`, поэтому на iOS иконкой на экране «Домой» станет скриншот страницы.
- `theme-color` всегда тёмный и не меняется вместе со светлой темой.
- **Сделать:**
  - Иконки `icon-192.png` и `icon-512.png` (purpose `any`).
  - Отдельная `icon-maskable-512.png` с полями.
  - `apple-touch-icon` 180×180.
  - `<meta name="theme-color" media="(prefers-color-scheme: …)">`; обновлять при смене темы.

### P2 — UX и доступность

**13. График.** Подсказка обещает «нажми на столбец, чтобы увидеть сумму», но сумма есть только в `title`, и по нажатию на телефоне ничего не происходит. Отрицательные дни рисуются вверх, нулевой линии нет.
→ Показывать значение над столбцом или по нажатию; добавить нулевую линию.

**14. Форма операции.**
- Быстрые кнопки «+1 500 ₽» показываются и в режиме расхода.
- У поля суммы нет `inputmode="numeric"`.
- У даты нет `max` равного сегодняшнему дню: можно выбрать будущую дату и только после этого получить ошибку.
- Лимит в 744 часа на одну операцию слишком велик: для одной смены разумно не больше 24.

**15. Разная сортировка.** «Последние операции» на главной сортируются только по дате, а история — по дате и `ts`, поэтому операции одного дня идут в разном порядке.
→ Использовать одну функцию сортировки.

**16. Удаление.**
- Удаление идёт только через `confirm()`, отменить его нельзя.
  → Тост «Удалено · Отменить» на 5 секунд.
- Если удалить операцию, открытую на редактирование, `editingId` не сбрасывается, и «Сохранить» создаёт её заново.

**17. Доступность.**
- У кнопок «◐» (тема) и «➤» (отправить) нет `aria-label`.
- У тоста нет `role="status"` или `aria-live`.
- В навигации нет `aria-current`, у переключателя типа операции — `aria-pressed`.
- В графике `aria-label` стоит на `<i>` без роли, и экранные дикторы его игнорируют.
- Шрифты 10–11 px.
- Контраст статусов ниже WCAG AA (нужно 4,5:1) ✅: «Отстаёшь от плана» — 3,0:1, «Опережаешь план» — 3,8:1.
- Кнопка темы переключает auto → dark → light, а иконка показывает итоговую тему, поэтому режим «auto» не отличить.

**18. Тост закрывает навигацию** ✅. На iPhone с полоской «Домой» тост (`bottom: 85px`) перекрывает нижнюю навигацию.
→ Использовать `calc(… + env(safe-area-inset-bottom))`.

**19. AI-ответы.** Модель отвечает в Markdown, а ответ выводится как текст (`textContent` + `pre-wrap`), поэтому видны `**` и `###`.
→ Сделать безопасный минимальный рендер (жирный шрифт, списки) без `innerHTML` с сырым текстом или попросить модель отвечать без разметки.
- История чата пропадает при перезагрузке.

**20. Поиск в истории.** Запрос «доход» не находит доставки, хотя это тоже доход.

### P3 — качество кода

**21. Нечитаемый код.** Весь JS — минифицированные однострочники в `index.html`: однобуквенные имена, дублирование. `render()` уже вызывает `history()`, а обработчик удаления вызывает `render(); history()` ещё раз.
- Разнести на `styles.css` и ES-модули (`storage.js`, `calc.js`, `ui.js`, `ai.js`) без сборщика.
- Отформатировать код, добавить Prettier и ESLint.

**22. Нет тестов.** `QA_REPORT.md` перечисляет проверки, но их кода в репозитории нет. Браузерный E2E, по словам самого отчёта, не запускался.
- Добавить `package.json` и unit-тесты (Vitest или `node:test`) для `cleanEntries`, `cleanSettings`, `planAt`, `days`, экранирования CSV и подсчёта серии.
- Добавить Playwright E2E на основные сценарии и регрессионные тесты на пункты 1–4 и 9.
- Запускать тесты в GitHub Actions.

**23. Нет Content-Security-Policy.**
- После выноса JS в отдельные файлы добавить `<meta http-equiv="Content-Security-Policy">` (`default-src 'self'; connect-src 'self' https:; img-src 'self' data: blob:` …).
- HTML собирается строками через `innerHTML` с ручным `esc()`. Сейчас экранирование корректно, но такой подход хрупкий — лучше собирать DOM через `createElement` и `textContent`.

**24. Нет версии схемы данных.** У данных в `localStorage` нет поля версии. Добавить `schemaVersion` и функцию миграции, сохранив чтение ключа `moto-tracker-v1`.
